# Changelog

## Unreleased

- A role's public key has one source, `loadPublic(role)`: derived from the role's `.key`, and a `.pub` beside it that names another key is refused with `AGENTKEY_CONFLICT`. `pub`, `list`, `revoke`, `bind` and the ssh-agent signer read it, so a `.pub` copied over another role's no longer makes `pub` export, `revoke` revoke or `bind` vouch for the other key; `list` lists such a role with a conflict and exits 2. For a role whose `.key` was moved into ssh-agent (`agent-add --remove`), the `.pub` is accepted only when the agent holds that key under the comment `agentkey <role> <kid>`, so `pub`, `revoke` and `bind` of such a role now need the agent running. `readTrustedPub(file)` reads a trust directory's copy, which has no private key beside it. (AK-R01)
- `package-lock.json` is committed (lockfile version 3), so a checkout installs the dependency tree recorded at that commit and the gate builds each commit's dependencies from the commit itself. npm does not publish the lockfile, so installing `@optitransfer/agentkey` still pulls no required dependency. (AK-LOCK)

## 0.1.0 (2026-10-16)

- `AGENTKEY_SIGNER=ssh-agent` and `agentkey agent-add <role> [--remove]`: the role key goes into ssh-agent with the confirm constraint (as `ssh-add -c`), written on the agent socket so no OpenSSH key file is made, and with `--remove` the key file is deleted; signing then goes through the agent, each signature waits for a person's confirmation, and the agent's signature is checked against the role's public key before it is used. `sign --json` reports `signer: file | ssh-agent`; `agentSigner(role)` gives the same signer to `signDSSE`. (TB-05)
- `agentkey rotate <role>` and `rotate()`: a new key for the role, the old one kept under `rotated/`, and a rotation statement signed by the old key in `rotations/<old>-<new>.rotation.dsse`. A trust directory holding the statement accepts the new kid when the statement verifies under a trusted, unrevoked old key, and gives the old key a `not_after` of the rotation date; chains are followed; a statement that does not verify under the key it names refuses the directory. (TB-05)
- The identity model stated exactly in the README and in `docs/identity.md`: a role key is not a unique agent process, and the isolation options with what each gives. (TB-05)
- `setup` and `bind` from review findings (issues 6 to 11): a role public key is reused only with its matching private key; every trust destination is checked before the first write, a late failure removes everything the run made and restores `allowed_signers`, and the run ends by verifying the binding from the trust directory; a principal is one exact `allowed_signers` entry (`[A-Za-z0-9._@+-]`, not starting with `-`; wildcards, lists and comments refused); the trust key is compared by kid; the passphrase prompt decision uses stdin's tty flag and probes `/dev/tty` only on POSIX; the interop workflow falls back to `ubuntu-latest` when `RUNNER_LABEL` is unset. (AK-REV1)
- Small-order and non-canonical Ed25519 public keys are refused wherever a key enters (`kid`, `verifyDSSE`'s trusted keys, `agentkey verify --keys`, `bindingMessage`) with `AGENTKEY_UNSAFE_KEY`: libsodium's table of seven blocked encodings with the sign bit masked, a y at or past p, a second base64url spelling, and bytes that are no curve point, ported from hivevault with its test, which proves each row has an order dividing 8 and that node:crypto otherwise accepts a forgery under the identity key. `publicKeyProblem(bytes)` names the class. (AK-06)
- `trailer(kid, runId)`: the `Agent-Key` and `Agent-Run` commit trailer lines, refusing anything that could open another trailer. (AK-06)
- `.github/workflows/release.yml`: publishes to npm with `--provenance` on the `RUNNER_LABEL` runner (ubuntu-latest where it is not set), started by hand with the version, which must match package.json, and only after the suite passes. (AK-06)
- `agentkey setup <role> --principal <id> [--ssh-key <path>] [--trust <dir>]` and `setup()`: init, bind and the receiver's trust files (the role's `.pub`, `.pub.sshsig`, `.pub.principal` and the person's `allowed_signers` line) in one step. Every prerequisite is checked before anything is written; a missing piece exits 2 with the piece named, an existing key or binding is reused and never replaced, a second run writes nothing, and a passphrase key with no ssh-agent and no terminal is refused at once instead of waiting on the prompt. `--json` prints `{ role, kid, principal, trust, sign }`. (AK-SETUP)
- `signKeyless(payloadType, payload, opts)`: keyless Sigstore signing of a DSSE envelope with a Fulcio certificate for the CI job's OIDC identity (GitHub Actions, or `SIGSTORE_ID_TOKEN`), recorded in Rekor, returned with its Sigstore bundle for `cosign verify-blob-attestation`. `@sigstore/sign` 3.1.0 is an optional dependency loaded on first use; without it `signKeyless` throws `AGENTKEY_SIGSTORE_UNAVAILABLE`. The `sigstore-interop` workflow signs a fixture and verifies it with cosign; it runs only when started by hand. (AK-05)
- Licensing files for the public repository (AK-LIC): `NOTICE` names the copyright holder and the trademark terms (the Apache License grants no trademark rights; any fork uses its own name), `PATENTS-NONASSERT.md` is the interim patent statement (Apache-2.0 section 3 grants the patent licence), `CONTRIBUTING.md` says how work lands (tasks in `proofline.json`, a failing test first) and the Developer Certificate of Origin sign-off on each commit, with no contributor licence agreement, and `SECURITY.md` says how to report a vulnerability and what agentkey does and does not protect.
- `bind(role, sshKeyPath, principal)`, `verifyBinding(pub, allowedSigners, principal?)` and `agentkey bind <role> --principal <id> [--ssh-key <path>]`: the agent key signed by the human's SSH key with `ssh-keygen -Y sign -n agentkey`, stored as `<role>.pub.sshsig` and `<role>.pub.principal`, and checked with `ssh-keygen -Y verify` against an `allowed_signers` file as bound, unbound or invalid. Needs OpenSSH 8.0 or later. `revoke` moves the binding with the key. (AK-04)
- `agentkey` command line: `init`, `list`, `pub`, `sign`, `verify` and `revoke`, each with `--json`, and exit codes 0 ok, 1 verification failed, 2 unknown, revoked or expired key or missing input, 3 usage. `revoke` lists the kid in `keys/revoked.txt` before it moves the key to `revoked/`; `verify --keys <dir>` honours that list and a key record's `not_after`, checked at the time of verification or `--at`. (AK-03)
- `signDSSE`, `verifyDSSE`, `pae` and `statement`: DSSE envelopes with one Ed25519 signature per envelope, verification that lists each signature as verified, unknown or failed and fails the whole result on a failed known key, and in-toto Statement v1. Tested against DSSE's protocol test vector and against the sigstore verifier. (AK-02)
- `generate(role)`, `load(role)` and `kid(publicKey)`: one Ed25519 key per agent role, stored as PKCS8 PEM with mode 0600 under `$XDG_CONFIG_HOME/agentkey/keys` (`%APPDATA%/agentkey` on Windows, `AGENTKEY_HOME` overrides). A key file whose mode is not 0600 is refused with `AGENTKEY_INSECURE`. The key id is hivevault's replica key id scheme. (AK-01)
